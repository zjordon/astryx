# Astryx - 使用指南

> 生成时间: 2026-11-15 · 基于 main @ c87cb0c892 的 README.md、CONTRIBUTING.md、packages/core/README.md 与源码核查

本指南覆盖两种角色：**产品构建者**（在自己的应用里使用 Astryx）与**贡献者**（开发 Astryx 本身）。

## 1. 快速开始

### 1.1 环境要求

| 要求 | 版本 | 说明 |
|------|------|------|
| React | ≥19.0.0（peer） | ref 即 prop，无 forwardRef |
| Node.js | 消费者：≥22.13.0（CLI engines）；贡献者：24.x（`.nvmrc` = 24.22.1，22+ 可用） | Node 25+ 不再捆绑 Corepack |
| pnpm | 11.10.0（`packageManager` 钉死，仅贡献者需要） | 消费者可用 npm/yarn/pnpm/bun 任意包管理器 |
| 浏览器 | Lightning CSS 目标：chrome 123 / firefox 120 / safari 17.5（`light-dark()` 下限） | 源码构建通道的默认编译目标 |

### 1.2 安装（产品构建者）

```bash
# 组件库 + 主题 + StyleX 运行时 + CLI（开发依赖）
npm install @astryxdesign/core @astryxdesign/theme-neutral @stylexjs/stylex
npm install -D @astryxdesign/cli

# 也可全局安装 CLI（任一目录可用；项目内自动让位给项目自己的 CLI；两者并存是推荐配置）
npm i -g @astryxdesign/cli
```

> **务必使用带 scope 的 `@astryxdesign/cli`**：未加 scope 的 `astryx` 在 CLI 成为依赖前会解析到无关的 npm 包。CLI 未安装时 `npx @astryxdesign/cli <cmd>` 同样可用。

**最简接入（Next.js，无任何构建插件/PostCSS/Babel 配置）**：

```css
/* src/app/globals.css —— 顺序即层叠 */
@import '@astryxdesign/core/reset.css';        /* @layer reset */
@import '@astryxdesign/core/astryx.css';       /* @layer astryx-base 组件样式 */
@import '@astryxdesign/theme-neutral/theme.css'; /* @layer astryx-theme 令牌覆盖 */
```

```tsx
// src/app/providers.tsx
'use client';
import Link from 'next/link';
import {Theme} from '@astryxdesign/core/theme';
import {LinkProvider} from '@astryxdesign/core/Link';
import {neutralTheme} from '@astryxdesign/theme-neutral/built';

export function Providers({children}: {children: React.ReactNode}) {
  return (
    <Theme theme={neutralTheme}>
      <LinkProvider component={Link}>{children}</LinkProvider>
    </Theme>
  );
}
```

与 Tailwind 共存：在 `globals.css` 声明 `@layer reset, theme, base, astryx-base, astryx-theme, components, utilities;` 并置于 Tailwind import 之上（顺序颠倒会静默反转层叠）。Vite/CDN 路径见 `packages/core/README.md#quick-start`。

**AI 代理项目初始化**（把组件索引写进 `AGENTS.md`/`CLAUDE.md`，让代理不用猜）：

```bash
npx @astryxdesign/cli init
```

**package.json 脚本别名**（避免代理/新人直接调 CLI 的路径问题）：

```json
"scripts": {"astryx": "node node_modules/@astryxdesign/cli/clients/cli/bin/astryx.mjs"}
```

```bash
npm run astryx -- component --list
```

### 1.3 安装（贡献者）与快速运行

```bash
git clone --filter=blob:none https://github.com/meta/astryx.git
cd astryx
pnpm install          # Windows 上 pnpm 用 junction 链接，无需开发者模式

pnpm dev              # Storybook → http://localhost:6006（直接编译 src/，新克隆无需先 build）
pnpm test             # 全部单测（vitest ui + node + perf 三项目）
pnpm build            # 全部包（build→core→lab→charts→richtext→vega→native→8主题→CLI 资产捆绑→api-types）
pnpm docsite          # 文档站 → localhost:3000（首次需先 pnpm build）
```

## 2. 配置说明

### 2.1 消费者侧配置文件

**astryx.config**（项目根，TS/JS，经 jiti 载入）：

| 配置项 | 类型 | 说明 |
|--------|------|------|
| `integrations` | 数组 | 第三方 Astryx 集成包（贡献组件/主题/模板/文档/codemod） |
| `debug` | 函数 | 接收 CLI 运行遥测（`debug()` handler） |
| `cliCommand` | 字符串 | 集成声明的自定义 CLI 命令入口 |

**核心 CSS 导入**（顺序固定）：`reset.css` → `astryx.css`（或 lab/charts/richtext 各自的 `.css`）→ 主题 `theme.css`。深度集成（源码构建）改用 `@astryxdesign/build` 的 `withAstryx()`（Next.js）或 `astryxStylex()`（Vite）。

**主题内置对象**：`import {neutralTheme} from '@astryxdesign/theme-neutral/built'`（JS 对象，运行时注入）或纯 CSS `theme.css`（零 JS）。

### 2.2 贡献者侧关键配置

| 文件 | 作用 |
|------|------|
| `pnpm-workspace.yaml` | workspace 成员；`catalog:` 统一钉版（vite/stylex/babel/prettier/esbuild）；`overrides` 五条活性安全底线；`allowBuilds` 六个原生依赖白名单；`minimumReleaseAge: 10080`（7 天发布冷却） |
| `.nvmrc` | Node 版本唯一真源（CI 同读此文件） |
| `.gitattributes` | `* text=auto eol=lf`（全平台强制 LF，防 `--check` 字节比对失败） |
| `visual-gate.config.json` | 视觉门控截图预算 / 排除清单 |
| `.github/a11y-baseline.json` | axe 已知例外基线（只减不增） |
| `packages/core/package.json` `exports` | 177 个子路径**由 `scripts/sync-exports.js` 生成，禁手编**（`pnpm sync:exports:check` 校验） |

### 2.3 环境变量

| 变量 | 必需 | 说明 |
|------|------|------|
| `ASTRYX_SOURCE=1` | 否 | sandbox 从源码（而非 dist）运行（`dev:sandbox:source`；cmd.exe 需变通，见 Windows 报告） |
| `ASTRYX_STRICT_LINT=1` | 否 | lint 升到 CI 严重度（`lint:strict`） |
| `ASTRYX_STYLEX_BROWSER=1` / `ASTRYX_TURBOPACK_E2E=1` | 否 | `test:build` 中浏览器/turbopack 端到端段 |
| `NODE_DISABLE_COMPILE_CACHE` | 否 | 禁用 CLI 编译缓存 |
| `ASTRYX_VISUAL_GATE_READ_ONLY=1` | 否 | node 测试项目内自动设置，防视觉门控写盘 |

## 3. 主要功能

### 3.1 astryx CLI（18 个命令）

```bash
astryx help                        # 全部命令与选项（<500ms）
astryx init                        # 非交互初始化：装 agent 文档速查表，幂等
astryx component --list            # 按类别列全部组件
astryx component Button --dense    # 单组件全文档（props/变体/用法/解剖/无障碍契约）
astryx hook useListFocus           # 钩子文档
astryx docs                        # 参考文档主题列表（principles/tokens/theme/motion/icons…）
astryx docs theme --dense          # 整篇；--index 一节一行；<topic> <section> 取单节
astryx template --list             # 页面/区块模板目录
astryx template dashboard          # 输出整页源码；--skeleton 带空间注解的骨架
astryx theme list|add|use|remove|build|eject|template|targets|palette  # 主题组命令
astryx swizzle Button              # 弹出组件源码到项目自持
astryx upgrade --from 0.7.0 --apply# 版本迁移 codemod
astryx discover                    # 浏览/搜索可安装的集成与官方包
astryx search 表单                  # 跨组件/钩子/文档/模板/主题的 ranked 单列表
astryx build                       # 页面构建工作流向导
astryx doctor                      # 项目/计算机体检（~15 项带 id 检查）
astryx manifest --json             # CLI 能力清单（"CLI 的 OpenAPI spec"）
astryx gap-report                  # 报告缺失能力给所属包
astryx experimental icon|render|theme …  # 实验组
```

全局选项：`--json`（机器信封）· `--dense`（token 高效）· `--zh`（中文）· `--lang en|zh|dense` · `--detail full|compact|brief`。中文不是独立翻译框架，而是同目录 `.doc.zh.mjs` 覆盖层（部分对象覆盖而非整体替换）。

### 3.2 组件开发（贡献者）

标准目录（测试同目录，stories 在 Storybook 应用）：

```
packages/core/src/MyComponent/
├── MyComponent.tsx        # 实现（样式内联 stylex.create；'use client' 首行；JSDoc 头 @input/@output/@position）
├── MyComponent.test.tsx   # 同目录测试
├── MyComponent.doc.mjs    # ComponentDoc（props/示例/无障碍契约/中文覆盖层）
└── index.ts               # 公共导出（含可扩展 *VariantMap 接口）
```

规则要点：props 接口必须 `ref?: React.Ref<T>`（React 19，`@astryx/require-ref-prop`）；用户可见字符串走 `useTranslator()`（`@astryx/no-hardcoded-i18n-string`）；RTL 优先 CSS 逻辑属性 → `rtlStyles.mirror` → 事件时 `isRtlElement(el)` → 最后才是 `useDirection()`；包内 import 指向定义模块禁桶（`@astryxdesign/no-internal-barrel-import`）；新增语义图标需同步 `globalIconRegistry.tsx`/`defaultIcons.tsx`/CLI icons 文档三处。

### 3.3 主题开发

```bash
astryx theme eject my-theme                 # 从内置模板弹出主题工程（含 palette.config.json）
astryx theme palette generate --base "#1e66f5"  # 生成整套色板档位
astryx theme build src/myTheme.ts -o dist/theme.css
astryx theme targets                        # 可覆盖令牌清单
astryx experimental theme editor new        # 实验性：可视化主题编辑
```

主题源码即 `defineTheme({name, extends, tokens, typography, adaptations, components, icons})`；`[light, dark]` 元组编译为 `light-dark()`；组件级覆盖用 `components` 键 + 可选 `@light`/`@dark` 块。改已发布主题的 7 个包则在 `packages/themes/<slug>/` 内修改并运行对应 `generate-*-palette-refs.mjs`（`--check` 防漂移）。

### 3.4 测试与质量门禁（贡献者）

```bash
pnpm test                     # 全部；pnpm test:ui / test:node / test:ui:isolated 分项目
pnpm test:a11y-contract       # Playwright a11y 契约（先 storybook:build + playwright install chromium）
pnpm test:interaction         # 触控/动效交互证明（storyboards 加 @storyboard 过滤）
pnpm a11y:audit               # axe 审计 vs 基线；--components Button,Dialog 限定范围
pnpm rtl:audit -- --filter Avatar
pnpm guard:modal-close|disabled-hover|disabled-cursor|theme-layers   # 浏览器守卫探针
pnpm visual:plan|check|flaky  # 视觉门控
pnpm check:repo               # ~25 项仓库门禁
pnpm lint:strict              # CI 严重度 lint（含 check:repo）
pnpm specs:for <path>         # 查治理某路径的知识记录；--diff origin/main 查变更应遵循的声明
pnpm review:pre               # 请求评审前自检
```

## 4. API 接口

### 4.1 编程式 API（`@astryxdesign/cli/api`）

每个 CLI 命令都是返回 `{type, data}` 信封的函数，与 `--json` 输出**同构**：

```js
import {component} from '@astryxdesign/cli/api';
const res = await component({name: 'Button', detail: 'dense'});
// res = {type: 'component', data: {...}} —— 与 `astryx component Button --json` 完全一致
```

### 4.2 其他导出面

| 导出 | 用途 |
|------|------|
| `@astryxdesign/cli/authoring` | 撰写 `.doc.mjs` 的全部类型（ComponentDoc/CommandDoc/FunctionDoc/ReferenceDoc/EnumDoc/SchemaDoc…）+ zod 密封解析器 |
| `@astryxdesign/cli/host` | `runHostedCli({argv, cwd, cliCommand, integrations, ...})`——工具产品嵌入整个 CLI |
| `@astryxdesign/cli/json` / `config` / `debug` / `integration` / `template` / `codemod` / `doc` | 各子系统能力面 |
| `@astryxdesign/core/<Component>` | 组件子路径导入（177 个）；`/theme/tokens.stylex` 等样式模块；`/astryx.css` 预编译样式 |
| `@astryxdesign/build`（`.`/`babel`/`postcss`/`vite`/`next`） | 源码构建集成：`withAstryx()`（Next）、`astryxStylex()`（Vite）等 |

声明文件（`.d.mts`）从 `.mjs` JSDoc 生成（`pnpm -F @astryxdesign/cli sync:api-types`），gitignored、prepack 再生——**手写声明会撒谎，仓库用生成消除之**。

## 5. 常见问题

### Q: `pnpm docs` 打开了 npm 页面？
A: 与 npm 内建命令撞名。用 `pnpm docsite`（本地文档站）或 `pnpm astryx -- docs`（CLI 文档）。

### Q: Storybook "Failed to fetch dynamically imported module" / 改动不生效？
A: core 未构建或过期：`pnpm -F @astryxdesign/core build` 后重启；仍不行则硬刷新（Ctrl+Shift+R）并清 `apps/storybook/node_modules/.cache`。（正常源码开发免构建——Storybook 直接编译 src/，仅别名指向 dist 的场景需要。）

### Q: "Unexpected 'stylex.defineVars' call at runtime"？
A: StyleX 代码未经编译就运行了——检查 vite/webpack 配置是否把 `@astryxdesign/core` 指向了 `src/` 却没接 `@astryxdesign/build` 插件。

### Q: 消费项目里 `astryx` 命令找不到？
A: 用 package.json 脚本别名（§1.2）或 `pnpm exec astryx …` / `npx @astryxdesign/cli …`。注意未加 scope 的 `astryx` 在安装前解析到无关 npm 包。

### Q: Windows 上 `pnpm lint:strict` / `test:build` / `dev:sandbox:source` 报 "not recognized"？
A: 这三个脚本用了 POSIX 环境变量前缀。变通：`pnpm config set shell-emulator true`（一次性，用户级），或 PowerShell 手工 `$env:ASTRYX_STRICT_LINT='1'; pnpm exec eslint . --cache`。详见《Windows兼容性分析.md》。

### Q: core 包的 `exports` 字段被 CI 打回？
A: 该字段是生成物。跑 `pnpm sync:exports` 后提交，或先 `pnpm sync:exports:check` 本地验证。

### Q: PR 提交后 CI 不跑？
A: 三个原因对号：Draft 状态不跑 CI（标记 Ready 开始）；fork PR 需维护者加 `ci:run` 标签；改了 `.github/workflows/**` 的 PR 必须作者本人更新（GitHub 限制）。重浏览器套件用 `ci:run-visual`/`ci:run-a11y`/`ci:run-rtl` 标签按需加入。

### Q: 什么时候需要 Changeset？
A: 改了发布包的源码/CLI 行为/随包文档（`*.doc.mjs`、包 README）/`exports`/`bin`/依赖范围。用 `pnpm changeset:new`（自动探测改动包 + 类别推导 semver + 署名）。stories、sandbox、测试、夹具、CI、私有与 canary 包不需要。CI 的 `changeset-coverage` 会精确打回。
